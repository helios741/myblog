拓展2: 渐进式图片！

图片？

这种一边下载一边显示图片的流式展示技术，通常被称作“渐进式图片”（progressive image）。它采用的是渐进式图像编码技术，即在一张图片中同时包含了多个分辨率、不同质量的编码数据，并通过一定的编码算法和解码方式来实现渐进式地显示图像的效果。

具体来说，渐进式图片的编码格式通常是基于 JPEG、PNG、WebP 等格式进行的，而其解码方式则可以通过浏览器原生支持的方式进行，也可以通过 JavaScript 代码进行控制和扩展。当浏览器对渐进式 JPEG 图片进行解码时，它会先下载和显示基础分辨率的编码数据，并逐步下载和显示更高分辨率、更高质量的数据，从而实现了流式展示的效果。

需要注意的是，渐进式图片并不是一种具体的协议，而是一种编码和解码技术。这种技术在很多网站中得到广泛的应用，特别是在移动端网络流量较低、带宽较卡的情况下，能够提高页面的加载速度和用户的体验。

拓展4: 实时通信用什么协议！



和WebRTC的区别？

流式传输（streaming）方式可以提高视频和音频传输的实时性和效率，但是它和 WebRTC 在技术原理和应用场景上还是有所不同。

流式传输是通过 HTTP 协议来传输音视频数据流的，其传输模式包括两种：一是基于 HTTP 的 DASH（Dynamic Adaptive Streaming over HTTP）或 HLS（HTTP Live Streaming）等协议，二是基于传统的 RTSP 协议和 RTP 传输协议等。无论是哪种传输方式，都需要使用一个中间服务器来存储和分发音视频数据，客户端通过请求服务器获得音视频数据，服务器将分段的数据传输给客户端，客户端在接收到数据后进行解码以播放视频。

而 WebRTC 是一种基于 P2P 技术的实时通信技术，它可以直接在两个浏览器之间传输音视频数据，避免了中间服务器的传输和存储，能够实现更低的延迟、更高的实时性和更好的端到端加密等功能。

综上所述，虽然流式传输和 WebRTC 都可以实现音视频的实时传输，但技术原理、应用场景和优劣势都有所不同。流式传输主要适用于点播、直播等一些需要传输媒体资源的场景；WebRTC 则更适用于实时通信、音视频会议等需要点对点通信、低延迟的场景。
